Commandes HDFS — Manipulation des fichiers
25 min À faire
Entrer dans le conteneur master pour exécuter toutes les commandes HDFS :
Entrer dans le master
$ docker exec -it cluster-master bash
root@hadoop-master:/# ← vous êtes dans le conteneur ✅
1. Créer l'arborescence utilisateur
$ hadoop fs -mkdir -p /user/root
2. Créer le dossier input
$ hdfs dfs -mkdir input
3. Lister les fichiers
$ hdfs dfs -ls
Found 1 items
drwxr-xr-x - root root 0 /user/root/input
4. Lister récursivement avec taille lisible
$ hdfs dfs -ls -R -h ./
5. Copier purchases.txt vers HDFS
$ hdfs dfs -put /shared_volume/purchases.txt .
✅ Fichier copié vers HDFS
6. Vérifier — noter le facteur de réplication
$ hdfs dfs -ls -R
-rw-r--r-- 3 root root 482 purchases.txt
↑ 3 = facteur de réplication (3 copies sur 3 nœuds)
7. Afficher le contenu
$ hdfs dfs -cat purchases.txt
8. Afficher la fin du fichier
$ hdfs dfs -tail purchases.txt
9. Supprimer le fichier
$ hdfs dfs -rm purchases.txt
✅ Deleted purchases.txt
10. Remettre le fichier (copyFromLocal)
$ hdfs dfs -copyFromLocal /shared_volume/purchases.txt ./input
11. Changer les droits
$ hdfs dfs -chmod go+w ./input/purchases.txt
12. Déplacer un fichier
$ hdfs dfs -mv /user/root/input/purchases.txt /user/root/
13. Télécharger depuis HDFS
$ hdfs dfs -get ./input/purchases.txt /shared_volume/achat.txt
14. Copier dans un autre emplacement HDFS
$ hdfs dfs -cp ./input/purchases.txt ./purchases.txt

Télécharger alice.txt depuis Internet

15. Créer le dossier web_input
$ hdfs dfs -mkdir -p web_input
16. Télécharger alice.txt
$ wget http://www.textfiles.com/etext/FICTION/alice.txt
✅ alice.txt téléchargé
17. Copier vers le volume partagé
$ cp alice.txt /shared_volume/
18. Ingérer dans HDFS
$ hdfs dfs -put /shared_volume/alice.txt web_input
19. Vérifier
$ hdfs dfs -ls web_input
Found 1 items
-rw-r--r-- 3 root root 152K web_input/alice.txt
Question de validation
Dans le résultat de hdfs dfs -ls -R, vous voyez le chiffre 3 devant purchases.txt. Que signifie-t-il ?
Correct. Le facteur de réplication par défaut dans HDFS est 3. Si un DataNode tombe, les données restent disponibles sur les 2 autres — c'est la tolérance aux pannes.
C'est le facteur de réplication. HDFS réplique automatiquement chaque fichier sur 3 nœuds. Si 1 nœud tombe, les données existent encore sur les 2 autres.

Tester HDFS avec l'application Java (Hadoop API)
15 min À faire
Le JAR hadoop-hdfs-app.jar contient une application Java qui utilise l'API Hadoop FileSystem pour interagir avec HDFS. Il est déjà présent dans le conteneur master (dans /shared_volume/ ou /root). Si nécessaire, vous pouvez le copier depuis /shared_volume/hadoop-hdfs-app.jar.
📁 Opération 1 — status — Vérifie l'existence et les métadonnées d'un fichier dans HDFS.
En Java : FileSystem.get(conf).getFileStatus(path) → récupère la taille, les permissions, le propriétaire, le bloc de réplication, etc.
Commande
# hadoop jar hadoop-hdfs-app.jar status /user/root alice.txt
✅ File found: /user/root/alice.txt
Owner: root, Group: root, Size: 152345 bytes, Replication: 3, Permission: rw-r--r--, Modification time: 2025-03-27 10:23:45
📋 Opération 2 — info — Affiche les block locations (sur quels DataNodes se trouve chaque bloc).
En Java : FileSystem.get(conf).getFileBlockLocations(fileStatus, 0, length) → liste des hôtes pour chaque bloc.
Commande
# hadoop jar hadoop-hdfs-app.jar info /user/root purchases.txt
Block 1: 192.168.96.2:50010 (cluster-slave1), 192.168.96.3:50010 (cluster-slave2), 192.168.96.4:50010 (cluster-master)
Block 2: 192.168.96.3:50010 (cluster-slave2), 192.168.96.2:50010 (cluster-slave1), 192.168.96.4:50010 (cluster-master)
Total blocks: 2 | Replication factor: 3
📖 Opération 3 — read — Lit et affiche les 1 024 premiers octets du fichier.
En Java : FileSystem.open(path) → FSDataInputStream, lecture d'un buffer.
Commande
# hadoop jar hadoop-hdfs-app.jar read /user/root purchases.txt
--- Début du fichier ---
date,product,amount,category
2025-03-01,Laptop,1200,Electronics
2025-03-02,Book,25,Education
2025-03-03,Headphones,80,Electronics
... (seulement les 1024 premiers octets sont affichés)
✍️ Opération 4 — write — Crée un nouveau fichier texte dans HDFS et écrit une ligne dedans.
En Java : FileSystem.create(path) → FSDataOutputStream, écriture d'une chaîne.
Commande
# hadoop jar hadoop-hdfs-app.jar write /user/root hello.txt
✅ File created: /user/root/hello.txt
Content written: "Hello from Hadoop Java API !"
Après avoir exécuté write, vous pouvez vérifier avec hdfs dfs -cat /user/root/hello.txt que le fichier contient bien le message.
Question de validation
Dans l'API Hadoop Java, quelle classe est utilisée pour ouvrir un fichier en lecture sur HDFS ?
Bravo ! FileSystem.get(conf).open(path) retourne un FSDataInputStream qui permet de lire des fichiers HDFS de manière distribuée.
La bonne réponse est FileSystem.get(conf).open(path). L'API Hadoop utilise FileSystem comme point d'entrée, pas les classes standard de Java I/O.
