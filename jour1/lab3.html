Calcul de Pi — Demonstration du parallelisme MapReduce
8 min A faire
Comment MapReduce calcule Pi ? Methode Monte Carlo distribuee

Imaginez un carre de cote 1 contenant un quart de cercle de rayon 1. On lance des millions de points aleatoires dans le carre. La proportion de points tombant dans le cercle est proche de Pi/4.

MAP : chaque noeud genere N points aleatoires et compte combien tombent dans le cercle.
REDUCE : agrege les compteurs de tous les noeuds et calcule Pi = 4 x (points dans cercle / total).

Plus on lance de maps et d'echantillons, plus Pi est precis.
Input
2 Maps
1000 pts chacun
→
MAP
Map 1 : 786 pts OK
Map 2 : 791 pts OK
→
SHUFFLE
Agregation
automatique
→
REDUCE
Pi ≈ 3.14159
Lancer le calcul de Pi (2 maps x 1000 echantillons)
$ hadoop jar $HADOOP_HOME/share/hadoop/mapreduce/hadoop-mapreduce-examples-3.2.0.jar pi 2 1000
Number of Maps = 2
Samples per Map = 1000
Job Finished in X seconds
Estimated value of Pi is 3.14800000000000000000
Decrypter la sortie :

Number of Maps = 2 : 2 taches Map lancees en parallele sur les noeuds du cluster
Samples per Map = 1000 : chaque Map genere 1000 points aleatoires
Total = 2000 points : estimation peu precise car peu de points
Pi estime ~ 3.148 : different de Pi reel (3.14159) — normal avec seulement 2000 points

Essayez avec plus d'echantillons :
Version plus precise (optionnel)
$ hadoop jar $HADOOP_HOME/share/hadoop/mapreduce/hadoop-mapreduce-examples-3.2.0.jar pi 10 10000
Question 1 / 2
Si vous passez de pi 2 1000 a pi 50 100000, que se passe-t-il ?
Exactement. Maps contrôle le parallelisme, Samples contrôle la precision. 50 maps x 100 000 pts = 5 millions de points : estimation tres proche de 3.14159. Le calcul sera aussi distribue efficacement sur le cluster.
Plus de Maps = plus de parallelisme = plus vite. Plus de Samples = plus de points aleatoires = estimation plus precise de Pi. Avec 5 millions de points (50 x 100 000), Pi sera tres proche de 3.14159.
Question 2 / 2
Dans un contexte bancaire, quel probleme similaire pourrait etre resolu avec ce paradigme de calcul distribue ?
Excellent exemple. La VaR Monte Carlo est exactement ce type de calcul : lancer des millions de simulations de marche independantes (MAP), puis agreger les resultats pour obtenir le quantile de perte (REDUCE). C'est un cas d'usage reel de MapReduce dans les salles de marche.
La VaR Monte Carlo est le meilleur exemple : simuler des millions de scenarios de marche independants (MAP sur plusieurs noeuds), puis agreger pour obtenir le quantile de perte maximal (REDUCE). C'est exactement le meme paradigme que le calcul de Pi.

WordCount Java — Le "Hello World" de MapReduce
12 min A faire
Le principe WordCount en 3 phases :

MAP : pour chaque ligne du fichier, decouper en mots et emettre (mot, 1)
SHUFFLE : Hadoop regroupe automatiquement toutes les paires par mot — (alice, [1,1,1,...])
REDUCE : pour chaque mot, additionner tous les 1 et emettre (alice, 221)
Texte input
"alice was
alice said"
→
MAP
(alice,1)
(was,1)
(alice,1)
(said,1)
→
SHUFFLE
alice:[1,1]
said:[1]
was:[1]
→
REDUCE
alice 2
said 1
was 1
Preparer les donnees
Verifier que alice.txt est dans HDFS
$ hdfs dfs -ls /user/root/web_input/
Found 1 items
-rw-r--r-- 3 root root 152K /user/root/web_input/alice.txt
Si alice.txt est absent : hdfs dfs -put /shared_volume/alice.txt /user/root/web_input/
Lancer le job WordCount
Executer wordcountJob.jar
$ hadoop jar /shared_volume/wordcountJob.jar \
/user/root/web_input/alice.txt \
/user/root/output/wordcount_java
INFO mapreduce.Job: map 0% reduce 0%

Question 1 / 2
Le fichier de resultat s'appelle part-r-00000. Que signifie ce nom ?
Exactement. part-r-NNNNN = sortie du Reducer NNNNN. Avec 1 reducer (defaut), vous obtenez un seul fichier. Avec 3 reducers configures, vous auriez part-r-00000, part-r-00001, part-r-00002 contenant chacun une portion des resultats.
Ce nom indique le numero du Reducer. part-r-00000 = Reducer 0. Avec un seul reducer (defaut de WordCount), tout le resultat est dans un fichier. Augmenter le nombre de reducers produit plusieurs fichiers part-r-NNNNN.
Question 2 / 2
alice.txt fait 152 Ko. Si le fichier faisait 152 Go, qu'est-ce qui changerait dans l'execution MapReduce ?
Exactement — c'est la force de MapReduce. 152 Go = ~1220 blocs HDFS de 128 Mo. Hadoop lancera jusqu'a 1220 Mappers en parallele, chacun traitant sa portion. C'est la scalabilite horizontale en action.
MapReduce est concu pour les tres grands fichiers. HDFS decoupe automatiquement en blocs de 128 Mo. Chaque bloc est traite par un Mapper distinct en parallele. Plus le fichier est grand, plus le parallelisme est efficace.

WordCount Python — Hadoop Streaming
12 min A faire
Hadoop Streaming : executer n'importe quel script (Python, Ruby, Bash...) comme job MapReduce.

Principe : Hadoop passe les donnees au Mapper via stdin et recupere les resultats via stdout. Pas besoin d'API Java — n'importe quel langage suffit.

Pourquoi sort -k1,1 ? Entre mapper et reducer, le Shuffle de Hadoop trie toutes les paires par cle avant d'appeler le Reducer. En local, sort -k1,1 reproduit ce comportement indispensable.
Tester le mapper seul
Le mapper lit chaque ligne et emet une paire (mot, 1) par mot. Tester en local avant de lancer sur Hadoop.
Voir les paires (mot, 1) generees
$ cat /shared_volume/alice.txt | python3 /shared_volume/mapper.py | head -20
Alice 1
was 1
beginning 1
to 1
very 1
tired 1
Tester mapper + reducer en local
Pipeline local complet (sans Hadoop)
$ cat /shared_volume/alice.txt \
| python3 /shared_volume/mapper.py \
| sort -k1,1 \
| python3 /shared_volume/reducer.py \
| sort -k2 -rn | head -10
the 1818
and 940
to 809
Memes resultats que la version Java
Lancer via Hadoop Streaming
Localiser le JAR Streaming
$ find /opt -name 'hadoop-streaming*.jar'
/opt/hadoop-3.2.0/share/hadoop/tools/lib/hadoop-streaming-3.2.0.jar
Lancer WordCount Python sur Hadoop
$ hadoop jar /opt/hadoop-3.2.0/share/hadoop/tools/lib/hadoop-streaming-3.2.0.jar \
-files /shared_volume/mapper.py,/shared_volume/reducer.py \
-mapper "python3 mapper.py" \
-reducer "python3 reducer.py" \
-input /user/root/web_input/alice.txt \
-output /user/root/output/wordcount_python
packageJobJar: [mapper.py, reducer.py]
INFO mapreduce.Job: map 100% reduce 100%
INFO mapreduce.Job: Job completed successfully

to 809
Identique a la version Java
Question 1 / 2
Pourquoi le sort -k1,1 est-il indispensable entre le mapper et le reducer dans le test local ?
Exact. Le Shuffle est l'etape centrale de MapReduce : Hadoop trie et regroupe toutes les paires par cle avant le Reducer. Sans ce tri, le reducer verrait alice 1, the 1, alice 1 au lieu de alice 1, alice 1, ..., the 1, the 1. Il sous-compterait. En local, sort -k1,1 reproduit ce comportement.
Le sort -k1,1 simule le Shuffle de Hadoop. En production, Hadoop trie automatiquement toutes les paires par mot avant d'appeler le Reducer. Le Reducer de WordCount suppose que toutes les occurrences d'un meme mot arrivent ensemble — sans tri, il sous-compterait les frequences.
Question 2 / 2
Le fichier Python Streaming s'appelle part-00000 (sans le "r"). Pourquoi cette difference avec la version Java (part-r-00000) ?
Exactement. L'API Java MapReduce nomme les fichiers part-r-NNNNN (r = reducer). Hadoop Streaming utilise un OutputFormat different qui genere part-NNNNN. Le contenu est strictement identique — le top 10 est le meme dans les deux cas.
C'est une difference technique entre les deux frameworks. L'API Java genere part-r-NNNNN, Hadoop Streaming genere part-NNNNN. Le contenu est identique — comparez les top 10 pour vous en convaincre.

Exercice finance — WordCount sur purchases.txt

Contexte : appliquer WordCount sur des donnees de transactions bancaires (purchases.txt) pour identifier les categories de produits les plus frequentes. C'est un exemple simplifie d'analyse de portefeuille — en production, Spark SQL ferait des agregations bien plus sophistiquees.

Resultats selon votre fichier purchases.txt
Question de synthese
En contexte bancaire reel, quelle est la principale limitation de WordCount pour analyser des transactions financieres comme purchases.txt ?
Exactement. WordCount traite chaque ligne comme du texte brut sans connaitre la structure (date, client, montant, categorie). Pour des analyses financieres reelles, on utilise Spark SQL qui comprend le schema, permet les filtres, les jointures et les agregations (SUM, AVG, GROUP BY). C'est ce que nous verrons au Lab 5.
La vraie limitation est structurelle : WordCount ne comprend pas le schema des donnees. Il compte "Electronics" comme un mot, mais ne peut pas calculer "total des ventes Electronics". Pour cela, il faut Spark SQL ou un job MapReduce personnalise qui parse le CSV correctement.
